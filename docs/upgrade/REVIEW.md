## Review 守则

1. 每次 Implementer 提交代码后，在此登记 review 项
2. Review 关注：架构一致性、代码质量、是否偏离 PLAN.md 设计
3. 发现问题记录在"反馈"列，严重问题同步更新 PLAN.md
4. Review 通过后标记 ✅，有问题标记 ❌ 并说明

## 架构合规检查清单

每次 Review 时对照检查：

- [ ] 是否遵循 AgentLoop 多轮迭代模式（非单次调用）
- [ ] 工具调用是否通过 Function Calling 协议（非文本解析）
- [ ] 新增的游戏能力是否以 Skill 形式注册（非硬编码子 Agent）
- [ ] 是否有评估环节（生成后能评估可玩性）
- [ ] 错误处理是否完善（LLM 失败、工具异常）
- [ ] 是否保持向后兼容（旧的 API 不能 break）
