# Snake v0 → fixed 调试日志

> 时间：2026-05-22
> v0 来源：Claude Opus 4.7 子 agent 生成（prompt: "做一个简单的贪吃蛇游戏，4-8岁玩"）
> oracle 对 v0 verdict：PASS（exit 0）
> 主会话亲自检视：v0 已是高质量可玩贪吃蛇

## 关键判定

**v0 不需要修复**。oracle PASS + 人工玩验证全部通过：
- 真实交互测试：点开始 → 蛇向右移动 → 反向键被防呆 → 撞墙触发 game over → 鼓励文案 → 再来一局 → 分数归零
- 全部行为符合预期

因此 `snake-fixed.html = snake-v0.html`（cp 一份）。

但这次 v0 的高质量本身就是 SKILL 演进的素材——**v0 做对了什么**应该写进 SKILL.md 让未来 LLM 生成时不偏离。

## v0 做对的关键点（→ SKILL 蒸馏候选）

### ✅ 普适改动 #1：keydown 绑到 document

```js
document.addEventListener('keydown', (e) => { ... });
```

**why 普适**：贪吃蛇典型偏差是 LLM 把事件绑到 button / canvas，需要 focus 才能控制。绑 document 一律可控。

### ✅ 普适改动 #2：方向 + WASD 同时支持

```js
if (k === 'ArrowUp' || k === 'w' || k === 'W') ...
```

**why 普适**：4-8 岁儿童家长可能用方向键，年龄稍大孩子可能用 WASD。Both = 兼容。

### ✅ 普适改动 #3：反向键防呆（dir + nextDir 解耦）

```js
let nextDir = dir;
function step() {
  if (nextDir.x !== -dir.x || nextDir.y !== -dir.y) dir = nextDir;
  // ...
}
function setDir(d) {
  if (d === 'up' && dir.y !== 1) nextDir = {x: 0, y: -1};
  // ...
}
```

**why 普适**：典型 LLM 偏差是直接 `dir = newDir`，导致蛇向右走时按左键瞬间反向 → 自撞 → 游戏立刻结束。
正确做法：keydown 写 nextDir，下次 tick 再判定是否反向再赋给 dir。

### ✅ 普适改动 #4：setInterval 驱动 tick，不靠 keydown

```js
timer = setInterval(step, 180);
```

**why 普适**：LLM 偏差是"只在按键时移动"。正确：tick 持续移动，keydown 只改方向。

### ✅ 普适改动 #5：score 用专门 DOM 元素 + 实时更新

```html
<span id="score">0</span>
```
```js
score += 10;
scoreEl.textContent = score;
```

**why 普适**：oracle 自动测试需要 score 钩子；用户也需要看到分数变化。

### ✅ 普适改动 #6：游戏结束态明确 + 重启入口

```js
function gameOver() {
  running = false;
  clearInterval(timer);
  ovTitle.textContent = '游戏结束';
  ovMsg.textContent = '本局得分 ' + score + ' 分。' + 鼓励文案;
  startBtn.textContent = '再来一局';
  overlay.classList.add('show');
}
```

**why 普适**：游戏结束态可见 + 鼓励而非惩罚（儿童友好）+ 一键重启。

### ✅ 普适改动 #7：每 tick clearRect 整画布

```js
function draw() {
  ctx.fillStyle = '#f4fff4';
  ctx.fillRect(0, 0, canvas.width, canvas.height);  // 等同 clearRect
  // ...
}
```

**why 普适**：典型 LLM 偏差是不清画布，蛇身像素累积造成拖影。

### ✅ 普适改动 #8：食物与蛇不重叠

```js
function placeFood() {
  while (true) {
    const fx = ...;
    if (!snake.some(s => s.x === fx && s.y === fy)) {
      food = {...}; return;
    }
  }
}
```

**why 普适**：直接 random 不检查会让食物生成在蛇身上，立刻被吃 → 视觉 bug。

### ⚠️ 个案改动（不进 SKILL）：localStorage 最高分

```js
best = parseInt(localStorage.getItem('snake_best') || '0', 10);
```

**why 个案**：是 nice-to-have，但不是"能玩"的必要项。SKILL 不应该写成强约束（增加 LLM 负担）。
可以作为 SKILL "评估重点" 的可选项提到。

## 对 oracle 自身的反思（**重要**）

第一次 oracle 跑 snake-v0 时判 FAIL（虽然 v0 真能玩），原因：
- canvas hash 在 baseline 1 秒就在自动变（蛇自动移动），被加入白名单 → 排除
- bodyText 仅变化 35 字符（"游戏结束 / 本局得 0 分..."），不到 50 字符阈值
- 所以 oracle 判"无信号"

修复：
1. bodyText 阈值从 50 降到 20
2. 加"游戏关键词"识别（出现"游戏结束 / game over / 失败 / 分数 / 再来"等关键词→强信号）
3. driver.py 在 result.json 里也存 bodyText 截断版（不只 hash），让 verdict 可读

修复后 v0 oracle PASS，self-test.sh 三 fixture 全过（keytest PASS / dead-page FAIL / snake-v0 PASS）。
