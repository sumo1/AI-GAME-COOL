# Memory 格式约定

> 任务实施过程中按天累积的决策备忘录。dreamer 整理时按这个格式解析。

## 文件命名

```
YYYY-MM-DD-{slug}.md
```

slug 用 kebab-case，如 `2026-05-21-sqlite-wal-mode-decision.md`。

## 单条 memory 的最小结构

```markdown
# {一句话标题}

> 时间：YYYY-MM-DD
> 上下文：{Step / 子任务 / 哪个 PR}
> 来源：{讨论 / 实施踩坑 / code review 反馈}

## 结论
{一句话：当时拍的板}

## 证据
- {支撑结论的事实，越具体越好}
- {被推翻的旧假设}
- {commit / 文件路径 / 错误日志}

## 被否决的方案（重要）
- {方案 X：未采用，原因}
- ...

## 影响范围
{这条决策影响哪些文件 / 模块 / 后续任务}
```

## 什么该写、什么不该写

✅ **该写**：
- 推翻了某个假设的事实（比如"以为 SQLite 有 BIGINT，结果只有 INTEGER"）
- 被否决的方案及其原因（高价值，dreamer 会保留）
- 跨子任务影响的决定（比如"决定用 sqlite-jdbc 3.x，所有 step 共享"）
- 接口契约的临时调整与原因

❌ **不该写**：
- "今天忘了跑 mvn test" 之类的流水账
- 已经在代码里说清楚的事
- 单纯的进度报告（写 progress.md 即可）

## dreamer 整理触发

- 任务收尾时
- 本目录 `.md` 文件 ≥ 10 条时
- 用户说"整理记忆"
